## 9. PHASE CYCLE OSCILLATOR: MAKING CYCLE ALIGNMENTS EASY TO READ

After reviewing the fundamental steps in a successful trading approach using the dominant cycle in the previous chapters, we can now focus on how to make this information more "human-readable."

Based on experience and trader feedback, it is not easy to read and interpret all cycle parameters for successful trading, even with a cycle engine "at hand." Forecasting market cycles is more of an art than simply determining buy and sell signals from a price chart. Therefore, it would be helpful to further optimize cycle output into a more "readable" format. Instead of mathematical phase values, presenting phases in a human-readable format like "approaching the top" or "starting downward trend" is more user-friendly.

Furthermore, experience shows that it is not prudent to focus solely on one dominant market cycle. Since multiple cycles are active simultaneously, traders must also pay attention to related markets or underlying indicators to gain insights into valid trading cycles. Different cycles across different markets can either neutralize overall price movements or amplify price behavior. Manually pulling daily information for all markets and applying cycle analysis multiple times for each market/indicator is a cumbersome process. To simplify this basic daily routine, the public MarketCycles API endpoint now incorporates an automated process to perform daily analysis for most major markets using the cycle engine.

The MarketCycles API and CycleExplorer API endpoints convert the dominant cycle into simple, human-readable text information about where we are in the current cycle. Based on MarketCycles' valuation criteria for key indices, the API output appears in a polished web dashboard on the public WhenToTrade website and is distributed via a daily email newsletter directly to subscribers. This provides an overview of dominant cycles in each market, information on cycles within cycles with a "phase modulation score" for current long- and short-term active cycles, and a broad view of related markets to validate inter-market cycle alignments—like checking the weather forecast at the start of the day.

However, users can create this type of pre-made, human-readable report on active cycles in financial markets by simply using the "phase status" API and "phasing score" return values. The web-based cycle dashboard is just one example of using the MarketCycles API endpoint—users can recreate these dashboards on their own, even in Excel or a Google Sheet.

#### Cycle Phases: Human-Readable Oscillator for Cycles Within Cycles

As previously mentioned, both cycle API endpoints include embedded cycles-within-cycles information based on the Phasing Score. The Phasing Score summarizes the phase status for two dominant cycles: a long-term cycle and its corresponding short-term dominant cycle. Both cycles are detected individually. The phase of each cycle is converted into a value oscillating between -100 and 100, so the Phasing Score oscillator is an easy-to-read indicator with values ranging from -200 to 200, where 200 indicates a perfect mathematical top alignment of both cycles, and -200 indicates a perfect bottom alignment.

The following examples (1-8) visualize the Phasing Score for different points in time. We detect and plot a long- and short-term cycle on the simplified chart. The blue line represents the analysis day and shows the "Phasing Score" result in the top-left corner of each window. Individual scores for each cycle can be found using the figure in the previous chapter, "The Perfect Cycle" (see Figure 9-5).

Examples 1-4 show possible topping cycles, their resulting Phasing Score, and whether the score value could be read as a valid signal.

![Figure 9-6](./assets/fig-9-6.png)

**Figure 9-6:** Cycle Phasing Score Examples 1-4

##### 1. Situation: Phasing Score = 0

   The long-term cycle is at the top ("Top Exiting" = 100), and the short-term cycle is in the current low ("Bottom Exiting" = -100). This results in a combined Phasing Score of zero. The two cycles cancel each other out. In this case, it is unclear which cycle is more dominant, and no trading signals can be derived from the oscillator.

##### 2. Situation: Phasing Score = 195 (Valid Signal)

   The long-term cycle is at a current top (100), and the short-term cycle has just passed the "Starting Downtrend" top (+95), resulting in a combined Phasing Score of 195. This is a near-perfect cycle-within-cycle alignment for a topping process.

##### 3. Situation: Phasing Score = 0

   The long-term cycle is in a downtrend (= -50), and the short-term cycle is in a current uptrend (= 50), resulting in a neutralized Phasing Score of zero. Thus, it is unclear which cycle is more dominant. In a theoretical world, a sideways movement would be expected.

##### 4. Situation: Phasing Score = 100

   Both the long- and short-term cycles are in a running uptrend (= 50), resulting in a combined Phasing Score of 100. In this case, both cycles confirm a running uptrend phase without exact knowledge of the next expected inflection point. Only a glance at the visual plot would show an approaching cycle top in the near future. However, this alignment is not derived from the pure Phasing Score value and requires additional verification with, for example, the Cycle Explorer.

To summarize the first four examples: Only the second situation was a valid signal for a market top. The other values do not allow us to derive trading information from oscillator-based alignment values for long- and short-term cycles.

The next examples (5-8) show possible bottoming cycles and their corresponding signal readings:

![Figure 9-7](./assets/fig-9-7.png)

**Figure 9-7:** Cycle Phasing Score Examples 5-8

##### 5. Situation: Phasing Score = -180 (Valid Signal)

   The long-term cycle is in an "Approaching Bottom" state (= -80), and the short-term cycle is in a "Bottom Exiting" state (= -100), resulting in a combined Phasing Score of -180: another perfect cycle alignment for a market bottom.

##### 6. Situation: Phasing Score = -110

   The long-term cycle is in an "Approaching Bottom" phase state (= -80), and the short-term cycle is in a "Neutral Downtrend" state (= -30). This results in a combined Phasing Score of -110, showing a downward trend still in progress without concrete knowledge of which cycle is more dominant in terms of timing to the next inflection point. The specific cycle duration for each cycle must be checked to project upcoming cycle alignments. In this example, visual inspection shows an upcoming cycle alignment in the chart. Therefore, additional visual plotting is needed to detect the next inflection point rather than relying solely on the Phasing Score.

##### 7. Situation: Phasing Score = -45

   The long-term cycle state is "Bottom Arriving" (= -95), and the short-term cycle is in a "Neutral Uptrend" state (= 50), resulting in a combined Phasing Score of -45. In such a situation, the Phasing Score is indifferent, similar to examples 6 and 4. In these cases, the visual plot must be checked for future cycle alignments. No trading information can be derived at these indifferent levels based solely on the Phasing Score.

##### 8. Situation: Phasing Score = -155 (Valid Signal)

   The long-term phase is in "Starting Uptrend" (= -95), and the short-term cycle phase is in a "Downtrend Exiting" phase (= -60), resulting in a combined Phasing Score of -155. In this case, both cycles confirm a possible bottoming phase in the dataset.

In this case, only examples 5 and 8 were valid trading signals based on the Phasing Score.

From reading these examples, it can be seen that we can derive valid signals if the Phasing Score readings

a) are above 150, indicating market tops, or
b) are below -150, indicating market bottoms.

Now, we convert the complex mathematics of analyzing dominant long- and short-term cycles into a simplified oscillator, which we can plot on the chart like any other indicator. This procedure turns complex cycle analysis into a simple, readable oscillator value swinging between -200 and 200, with upper and lower bands at 150 and -150, respectively. If the oscillator now reaches zones above or below these two bands, a cycles-within-cycles alignment is occurring. As with any oscillator, we only look at extreme readings indicating cycles-within-cycle alignments.

### 9.5 Cycle Phasing Score – NinjaTrader code section

Our cloud-based Application Programming Interface (API) provides the cycle phasing engine through a separate endpoint. Integrating the phasing calculation API allows us to use and integrate the phasing score across different platforms.

#### Key code section

```cs
protected override void OnBarUpdate()
{
  if (CurrentBar > 751) // Start once 700+ bars are available as lookback
  {
    string APIresultContent = "";

    // Get and prepare the close data array
    // --- prepare data
    closeList.Clear();
    for (int p = 0; p <= 750; p++)
      closeList.Add(Close[750 - p]);

    // Call the WhenToTrade Cycles CycleExplorer POST API endpoint
    // Load the close dataset via HTTP POST API call
    var content = JsonConvert.SerializeObject(closeList.ToArray());
    StringContent POSTcontent = new StringContent(content,
                         Encoding.UTF8, "application/json");

    // POST API call
    var response = client.PostAsync("/Api/CycleExplorer?MinCycleLength="
                  + minCycleLength + "&maxCycleLength=" + maxCycleLength
                  + "&plotForward=0&includeTimeseries=false&api_key="
                  + apiKey, POSTcontent).Result;

    // Check for network errors
    if (response.IsSuccessStatusCode)
    {
      APIresultContent = response.Content.ReadAsStringAsync().Result;
    }
    else
    {
      string msg = response.Content.ReadAsStringAsync().Result;
      Draw.TextFixed(this, "ApiError", "API error: " + msg,
                     TextPosition.TopLeft);
      return;
    }

    // Decode the cycle data returned by the API call
    var dominantCycle = JsonConvert.DeserializeObject<dynamic>(APIresultContent);

    // Check for API return errors?
    string statusCode = dominantCycle.StatusCode != null ?
                        dominantCycle.StatusCode : "";
    bool error = statusCode.IndexOf("error",
                  StringComparison.OrdinalIgnoreCase) >= 0;
    if (error)
    {
      Draw.TextFixed(this, "ApiError", "API error: " + statusCode,
                     TextPosition.TopLeft);
      return;
    }

    // Get cycle info from the returned object
    var cycleLength = dominantCycle.length;

    // Variant A: use dominant cycle score only
    // var cyclePhase = dominantCycle.phase_score;

    // Variant B: use combined long- and short-term cycle phasing score
    var cyclePhase = dominantCycle.PhasingScore;

    DominantCyclePhase[0] = cyclePhase;
  }
}
```
