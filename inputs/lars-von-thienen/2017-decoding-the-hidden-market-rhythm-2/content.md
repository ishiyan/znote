Positive feelings can make it easier to access information in the brain, promote creativity, improve problem solving, enhance negotiation skills, and foster efficient and thorough decision-making. Emotion facilitates optimal-choice behavior when a person is provided with several courses of action (Ackert, Church & Deaves, 2003).

The direct impact of emotions on financial markets is an ongoing controversial debate. However, a large body of literature exists which determines that emotion is an important aspect of the human condition that can enhance decision making. For example, if an investment went up 100% one year and then came down 50% the next, you wouldn't claim that you had an average return of 25% per year (the average formula is: 100% + (- 50%) / 2 = 25%). The investment is back where it started off: The real annualized gain is zero.

In this example, 25% represents the simple average, the "arithmetic mean". The zero percent that you actually get is the "geometric mean", also called the "annualized return" or the "CAGR" (Compound Annual Growth Rate). 

It is particularly misleading when you read fund advertisements that claim to have certain attractive "average annual returns". The average numbers make the funds look better than they really are.

The average return is incorrect because the value of the portfolio changes over time. Therefore, the order in which the returns occur is important. But if we take an arithmetic average, the order is not relevant. It would be the wrong approach to replace a method in which order is important (=calculation of profit) by a method in which order is not important (=arithmetic average). By using the geometric average, on the other hand, we obtain a number that is identical for each period. The more volatile an investment is, the higher the error between the average return and the CAGR you actually get. It is not surprising that investment firms often use the average return. Finance professionals use geometric averages.

Finally, we will use the compound annual growth rate that allows us to arrive at a clearer evaluation of the performance.

#### 9.3 Technical Indicator and Trading System Construction

We have to select a financial ‘vehicle’ which we will analyze based on the Metonic “emotions” cycles. First, we need a financial vehicle that has sufficient price history. We have to go back 19 years to evaluate the present day, and if we want to analyze the daily stock market data of the last two decades, we need a publicly available, continuous price history of at least 39 years. Once we have selected our financial vehicle, we need to develop a technical methodology to determine the sentiment of investors which drove the stock market n-years (days) ago. To keep the research simple, we will only check whether it was an up- or a down-day. If the close of the day was higher than the opening price, we will assume that stock market investor sentiment was positive (+1). If the close of the day was lower than the opening price, we will assume that it was negative (-1). It is therefore quite simple to determine investor sentiment n-days ago. The formula to analyze investor sentiment in pseudo-code is:

```easylanguage
(a) If Close[n]-Open[n] > 0 then sentiment_value[n] = +1
(b) If Close[n]-Open[n] < 0 then sentiment_value[n] = -1
```

As we will evaluate the recurrence of three cycles (19, 11 and 8 years), we need a technical approach which builds a composite score based on the sentiment 19, 11 and 8 years ago. Hence, we will summarize the sentiment score of these three cycles. Consequently, the formula for determining today’s sentiment score in pseudo code is:

```easylanguage
(c) Composite_sentiment_value[today] = sentiment_value [6393 days ago] + sentiment_value [4016 days ago] + sentiment_value [2922 days ago]
```

Finally, we must construct a new technical indicator which oscillates between -3 to +3 and which can be plotted like any technical indicator on the price chart. As the shortest cycle is 2922 calendar days (=8 year Metonic cycle), we can calculate the composite sentiment score into the future for the next 2921 bars from today. This indicator thus plots 8 years into the future and is fully independent from current price behavior.

Since we are using calendar days, the reference back to 6939, 4016 or 2922 days may lead to days in the past for which we have no price/sentiment history, for example, weekends. We therefore need a technical approach to bridge the non-existing price on weekends. We will simply use a moving average instead of absolute open/close values. The average will bridge the weekend and offers additional benefits: Mathematically, a moving average can be viewed as a low-pass filter used in signal processing. The moving average also evens out short-term fluctuations and filters out the “noise” which may not be related to the swings of human emotions. [8]

This entails two advantages: First, instead of using the noisy raw open/close values, we can use ‘smooth’ open/close values to calculate the sentiment score for each day. This will filter out noisy and abrupt short-term influences that disrupt our original theory. Second, we obtain smooth data for weekend/holiday gaps by using the previous open/close values for calculations on those days.

We will use a ‘Zero-Lag’ Exponential Moving Average (ZLEMA), which is a variation of the EMA. The Zero-Lag EMA tries to remove the lagging characteristic of the EMA to provide better price averaging and faster response to price swings.

For a given N-day period, the pseudo code is [9]:

```easylanguage
(d) ZLEMA = EMA of (price + (price - price[lag])) with lag = (N-1) / 2
```

Applying the Zero-Lag EMA gives us smooth open and close price data for each day of the week, including weekends and holidays, and will be used to calculate the sentiment score for any given day in the past. [10]

The approach will be kept simple on a straightforward cross-over rule:

- Long position: If the composite indicator moves beyond 1, we will go long the market. If the indicator moves back below 1, we exit the long position.
- Short position: If the composite indicator falls below -1, we will sell short the market. If the indicator moves back beyond -1, we will buy to cover the short trade.

**b) Statistical verification and significance test of performance metrics caused by chance**

Now we have to verify whether the observed superior trade system metrics are attributable to the Metonic cycles selected or whether we were just lucky. The simulation presented here tests the null hypothesis that the predicted long/short/neutral positions generated by the Metonic cycles strategy are random. The alternative research hypothesis is that the Metonic logic is so advanced that it can predict positions in such a way to produce superior trading system results.

This test is performed by generating a large number of system result samples (n=10,000), produced by using the same strategy applied during the same period. But instead of using the three previously used Metonic cycle lengths, we will use three randomly generated cycle lengths for each test. Using random cycle lengths instead of raw random trades to generate the strategy also has the benefit that similar trade distribution characteristics in the test collection are compared with our Metonic logic.

Because of the central limit theorem, the performance metrics derived from the test collection should be normally distributed, very similar to a system with random trade characteristics. If a normal distribution for the system result metrics can be confirmed, we can apply a statistical test to reject the null hypothesis. Thereby, we can determine whether the z-score and p-value of the result are attributable to chance.

Our test will control the trade performance characteristics of net profit, profitability, and profit factor.

We compute these three performance statistics of each system generated by random cycles and find the fraction of the collection whose performance metric equals or exceeds that of the Metonic cycles. This fraction is the probability that the supposedly superior performance of the Metonic model could have been obtained by nothing more than mere luck. If we find that this chance probability or p-value[13] is lower than a significance level of 1% (alpha=0.01), we can reject the null hypothesis. The results are shown in Figure 9 chart 1-3:

**c) Cross-validation with significance test to select cycles by chance with a realistic and reliable system**

As shown, the chance probability of selecting a trading system with 3 cycles, which performs similar or better than the Metonic cycles combination lies far below the significance level of 1%. However, as the derived performance metrics for the Metonic cycles are already very high, we need another form of evidence to cross-validate the chance probability.

In this test, we will lower the cut-off values that have to be achieved for each performance metric of the samples from our test collection to be qualified as a valid trading system. We will define a set of criteria which defines the minimum requirements for a reliable and profitable trading system. The conservative minimum levels used here are based on the fact that every investor will only accept a trading system which has:

A) at least positive performance metrics,
B) delivers a smooth and linear upward sloping equity curve, and
C) performs at least similar or better than the benchmark index in total equity return.

To derive a mathematical metric to measure the requirement (B) for a smooth and upward sloping equity curve, we will add another performance metric:

The Pearson product-moment correlation coefficient for the generated equity curve of the sample compared to the ideal linear upward sloping equity curve with the equity top set to the last bar. In mathematical terms, a smooth and near-linear upward sloping equity curve can be defined via a correlation coefficient higher than 0.6 between the observed and the ideal linear equity curve.

**Calculation of Correlation Coefficients for Equity Curve**

The figure below illustrates how the ideal equity between the observed and “ideal” equity is constructed: It is a linear upward sloping line from zero to the maximum equity from the observed test system at the end of the period.

![Figure](./assets/fig-9-9d.png)

**Figure: Correlation Coefficients Calculation**

Instead of simply using the overall Pearson correlation coefficient, we divide the period into three segments of the same length. We calculate a separate correlation coefficient for each segment while using part of the ideal and the observed system. We use this approach because the overall correlation could be misinterpreted. The shown example has an overall correlation coefficient of 0.93, which suggests a solid correlation and ideal equity curve for the test system. However, if you take a closer look at the first 7 years, the test system only realized losses and dropped below zero. No one would accept systems that generate constant losses over a period of 7 years. The segmented correlation scores reveal this effect with a negative coefficient of -0.71 for this period. So instead of simply measuring a cut-off level against the overall Pearson correlation, we measure the minimum cut-off level against all segments. This reflects reality more closely as we aim for systems which generate a constant upward sloping equity in each segment of approx. 7.2 years. As a result, even if the performance figures of the randomly selected cycles look good or better than the Metonic candidate, this system fails to meet our minimum requirements outlined in the statistics section, and is not part of the 147 systems.

#### 10.2 EasyLanguage Code for the Metonic Trading Strategy

```easylanguage
{ ** LvT Metonic Sentiment Strategy ** }

Inputs: len(13), c1(6939), c2(4016), c3(2922);

Variables: ac(0),ao(0),myval(0),myval1(0),myval2(0),myvalm1(0),myvalm2(0);

Array: compo_values[40000](0);

Const: tradingstartdate(900101);

// Calculate smoothed open/close values to bridge weekends & holidays
ac=ZLEMA(close,len);
ao=ZLEMA(open,len);

// Walk-forward calculation of metonic cycles composite indicator
// based on up- or downday situation
if ((ac-ao)>0) then
begin
   compo_values[CurrentBar+c1]=compo_values[CurrentBar+c1]+1;
   compo_values[CurrentBar+c2]=compo_values[CurrentBar+c2]+1;
   compo_values[CurrentBar+c3]=compo_values[CurrentBar+c3]+1;
end else
begin
   compo_values[CurrentBar+c1]=compo_values[CurrentBar+c1]-1;
   compo_values[CurrentBar+c2]=compo_values[CurrentBar+c2]-1;
   compo_values[CurrentBar+c3]=compo_values[CurrentBar+c3]-1;
end;

//Trading Section
If (CurrentBar>5) then
begin
   myvalm2=compo_values[CurrentBar-2];
   myvalm1=compo_values[CurrentBar-1];
   myval=compo_values[CurrentBar];
   myval1=compo_values[CurrentBar+1];
   myval2=compo_values[CurrentBar+2];
end;

// Entry & Exit check for Monday-Thursday
If (Date>tradingstartdate and DayOfWeek(Date)>0 and DayOfWeek(Date)<5) then
begin
   // long entry
   if (myval crosses above 1 and marketposition(0)<=0 ) then
      Buy next bar at open;

   // long exit
   if (myval crosses below 1 and marketposition(0)>0 ) then
      Sell next Bar at Open;

   // short entry
   if (myval crosses below -1 and marketposition(0)>=0 ) then
      Sellshort next bar at open;

   // short exit
   if (myval crosses above -1 and marketposition(0)<0 ) then
      BuyToCover next Bar at Open;
end;

// Check if friday and exit signal will be triggered on weekend?
If (Date>tradingstartdate and DayOfWeek(Date)=5) then
begin
   if ((myval crosses above -1 or myval1 crosses above -1 or myval2 crosses above -1) and marketposition(0)<0 ) then
      BuyToCover this Bar at Close;

   if ((myval crosses below 1 or myval1 crosses below 1 or myval2 crosses below 1) and marketposition(0)>0 ) then
      Sell this Bar at Close;
end;

// Check if we have sunday and a trade was triggered on the weekend or on friday?
If (Date>tradingstartdate and DayOfWeek(Date)=0) then
begin
   // long entry
   if ((myvalm2 crosses above 1 or myvalm1 crosses above 1 or myval crosses above 1) and marketposition(0)<=0 ) then
      Buy next bar at open;

   // short entry
   if ((myvalm2 crosses below -1 or myvalm1 crosses below -1 or myval crosses below -1) and marketposition(0)>=0 ) then
      Sellshort next bar at open;
end;
```

#### 6 Step: Switch to R1C1 cell reference type

R1C1 is a reference style for excel cells, just like the more ubiquitous A1 reference style. A1 works with a letter code for the column (A) and a number code for the row(1), with absolute positions preceded by the $ sign. The R1C1 reference works with numbers for both rows and columns, with the prefix R for Rows, and C for Columns, with the lack of numbers meaning you work in the same row and / or column as the formula. The numbers that follow R and C are either relative positions (between [ ]) or absolute positions (no [ ]).

Examples:

R[2]C refers to the cell two rows below the cell in which the formula’s in:

R[2] means two rows below, C without any number means same column

RC[-1] refers to the cell one column to the left: R without a number means same row as the formula, C[-1] without any number means same column

R1C1 refers the cell in the first row and first cell ($A$1): R1 is first row, C1 is first column.

So any numbers in square brackets refer to relative distance from the current cell. Unlike A1 which refers to columns followed by row number, R1C1 does the opposite: rows followed by columns (which does take some getting used to).

Positive numbers will refer to cells below and/or across to the right. Negative numbers will refer to cells above and/or to the left.

For example R[2]C[3] is a cell 2 rows down and 3 columns to the right. R[-1]C[-4] is a cell 1 row up and 4 columns to the left. If no number is shown in brackets then you are referring to the same row or column i.e. R[3]C will be a cell 3 rows below the current cell in the SAME column.

The reason activating this reference typ is that it will make coding our formulas much easier. As we refer to a static count into the past, the reference type is much more comfortable for us. As a trader we are also more familiar with refereces like close[1] which references to the close of the previous bar. This is now quite similar for references in the excel sheet.

To turn on, you’d have to go to Tools - Options - General, and then check R1C1 reference style.
